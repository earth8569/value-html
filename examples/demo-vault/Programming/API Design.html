API Design

#code #api

Summary

Predictable names, stable errors and small, versioned surfaces make an API pleasant to use for years.

Principles

Keep resources nouns and actions verbs. Prefer boring, consistent shapes over clever ones. Borrow the discipline of Ownership and Borrowing: be clear about who owns what.

Naming

Use plural collection names and stable identifiers. Never rename a field; add a new one and deprecate the old.

Errors

Return a machine-readable code, a human message and a request id. Document every code.

Versioning

Version in the path, support two versions at a time, and announce removals six months ahead.

Testing

Contract tests per endpoint (Testing Strategy) and a shared SQL Cheatsheet for the data layer.

Checklist

  • Names reviewed
  • Errors documented
  • Pagination tested
  • Rate limits documented
  • Code Review Habits applied
